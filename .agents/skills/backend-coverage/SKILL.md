# Backend Coverage Workflow

Maintain accurate Task × Backend coverage in `docs/BackendCoverage.md`
without claiming unverified support.

## 1. Read the sources of truth first

Parse the rules below from the files themselves on every run; never rely
on memory or hardcode criteria.

1. `docs/BackendCoverage.md` — authoritative status tokens, scoreboard,
   environments, known limitations, and remaining coverage.
   - Status tokens (`## Reading the tables`): **P** = inference ran and the
     expected output was checked; **RUNTIME-PASS** = inference ran, but output
     correctness or rendering still needs checking; **DR** = the example
     command passed automated checks, inference was NOT run; **B** = the
     backend builds in CI, this task untested on it; **U** = untested;
     **N/A** = the backend does not support this kind of task.
   - Scope (directly below the legend): a passing result applies to the
     tested model and environment, **not** every model in the family.
   - Backend abbreviations: **NERT** (Neuriplo Engine Runtime), **DNN**
     (OpenCV DNN), **ORT** (ONNX Runtime), **TRT** (TensorRT), **TRC**
     (LibTorch), **OV** (OpenVINO), **TF** (LibTensorFlow), **MGX** (the
     standalone MIGraphX backend, separate from ORT's MIGraphX provider),
     **GGML** (the standalone GGML backend), **LiteRT**, **ExecT**
     (ExecuTorch), **LLaMA** (llama.cpp, `LLAMACPP`), **KServe** (remote).
   - Two tables under `## Coverage by task`: `Local inference backends`
     (NERT/DNN/ORT/TRT/TRC/OV/TF) and `Additional runtimes and remote
     execution` (MGX/GGML/LiteRT/ExecT/LLaMA/KServe). Parentheses hold the
     model type and, when different, the example preset.
   - Freshness: the `Results last updated:` date, the `## Environments`
     table (tested version, recorded checks, notes), and gate evidence
     JSON under `docs/evidence/` must move together with any promotion.
2. `docs/generated/supported-model-types.md` — canonical `--type` strings
   and input contracts. Generated by
   `scripts/sync_supported_model_types.py`; never hand-edit.
3. `docs/Deployment.md#backends` — per-backend setup,
   `-DDEFAULT_BACKEND=<BACKEND>`, and Docker images (only some backends
   have `docker/Dockerfile.<backend>`; do not assume one exists for every
   backend). `docs/ExportInstructions.md` — per-backend model export
   requirements.
4. Cluster validation: `docs/SlurmBackendCoverage.md` plus
   `scripts/slurm_backend_matrix.py`. Weights and tensors stay out of git.

## 2. Scope the affected Task × Backend cell(s)

Identify every `(Task, Backend)` pair touched by the change or audit, in
both tables when the task appears twice (e.g. `rtdetr` rows exist in each
table with different representative presets). Confirm the `--type` string
against `docs/generated/supported-model-types.md`, not from memory.

## 3. Verify to the evidence level you claim

Configure from a fresh build directory (`cmake --fresh` or a new `-B`
dir) so a stale `DEFAULT_BACKEND` cannot leak into results. Claim only
the highest level actually demonstrated:

- **B**: the backend builds in CI (or its Docker image builds); no
  inference needed.
- **DR**: the example command passes automated checks without running
  inference (`integration-tests/local-inference-smoke`,
  `.github/workflows/e2e-example-emulation.yml`). Adding a preset also
  requires `list_presets`, the CI matrix entry, and a dry-run block in
  `app/test/test_docker_run_inference_e2e_example.sh` (see AGENTS.md).
- **RUNTIME-PASS**: inference ran (`neuriplo-infer` binary or a
  `docker_run_inference_e2e_example.sh` preset, `--no_display` in
  headless/container runs) with output under `data/output/`, but
  correctness/rendering is still unchecked.
- **P**: inference ran **and** the expected output was checked — non-zero,
  semantically valid predictions / annotated output in `data/output/`,
  valid `run_report.json` with per-stage timings, rendered outputs checked
  where applicable. Record the exact model file and environment; the P
  covers that model + environment only.

Backend-specific notes:

- GPU-only backends (TRT, MGX): without the hardware (NVIDIA GPU +
  Container Toolkit; ROCm / AMD hardware), never claim above the level
  actually reached — record hardware validation under remaining coverage.
- GGML: strict-GGUF-only loader (`.gguf` via the sibling
  `convert_onnx_to_gguf.py` converter); `scripts/ggml_app_gate.py`
  defaults to that converter. No CI build job — gates are local/manual.
- KServe: HTTP vs gRPC results are tracked separately; see
  `docs/KserveCompatibility.md` for protocol status.

## 4. Update `docs/BackendCoverage.md`

- Touch only cells backed by fresh evidence from step 3.
- Move the `Results last updated:` date, the matching `## Environments`
  row (tested version, recorded checks, notes), and new gate evidence
  JSON in `docs/evidence/` together with every promotion.
- Keep both tables consistent: same `(Task, Backend)` status, same
  parenthesized `type` / preset convention.
- `## Known limitations`: remove items whose blocker is now verified
  (cite what closed it — e.g. upstream `neuriplo` / `neuriplo-tasks` /
  `nert` pin bump or export fix); add newly discovered blockers with the
  concrete failure mode (unsupported ONNX op/schema, dynamic-shape
  restriction, missing preprocessing path, upstream repo boundary).
- `## Remaining coverage`: remove newly covered items (e.g. former **DR**
  combinations now run live); add new hardware/export gaps found.
- Cross-doc consistency: capability claims in `README.md`,
  `docs/Deployment.md`, and `docs/ExportInstructions.md` must not
  contradict the updated status.

## Guardrails

- Never inflate coverage: partial support (one model family passes while
  sibling architectures in the same task fail, or compile-only without
  E2E output validation) stays at **RUNTIME-PASS** / **DR** / **B** —
  never **P**.
- Respect repository boundaries (AGENTS.md system overview): backend
  runtime bugs belong in `neuriplo` (or `nert`), pre-/post-processing and
  task logic in `neuriplo-tasks`, CLI/pipeline/coverage orchestration in
  `neuriplo-infer`. File open items under the owning layer.
- Keep private validation data out of git: never commit credentials,
  hostnames, or unapproved test media.
- A new task type additionally triggers the AGENTS.md `Documentation
  checklist when wiring a new task type` (TaskFactory list sync,
  `## Key Features` bullet, routing in
  `app/src/NeuriploInferTaskRouting.cpp`).
